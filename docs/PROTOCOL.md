# Aegis TCP 验证协议（客户端对接）

默认端口 **9002**。与旧 verifySystem 客户端兼容。

## 帧格式
```
[4字节大端长度 L][payload(L字节)]
payload = "VERIFYSYSTEM|<app_id>|<api_id>|<密文>"
```
- 入站密文：`Base64( RC4( JSON明文, key = app_id字符串 ) )`
- 出站密文：`RSA_Base64(rc4key) + "," + Base64( RC4(JSON, rc4key) )`（RSA 公钥加密 16 字节 rc4key；客户端用内置私钥解）
- RSA 模数/私钥见旧客户端（未改动）。

## 通用字段
- 每个请求 JSON 必带 `ts`（当前秒级时间戳，与服务器相差 ≥1800 秒拒绝）。
- 需要登录态的接口（`api_id ≥ 500`）带 `token`（登录返回的）。

## 软件模式
每个软件有 `mode`：`card`（卡密）或 `user`（账号密码）。服务端据此分流。

## api 一览

| api_id | 含义 | card 模式请求字段 | user 模式请求字段 |
|---|---|---|---|
| 300 | 登录 | `Key, hwid` | `username, password, hwid` |
| 301 | 换绑机器码 | `Key, hwid` | `username, password, hwid` |
| 302 | 查询 | `Key` | `username` |
| 303 | 公告 | （无） | （无） |
| 304 | 更新信息 | （无） | （无） |
| 305 | 解绑机器码 | `Key, hwid` | `username, password, hwid` |
| 306 | 用卡激活注册账号 | —（不适用） | `card, username, password, hwid` |
| 307 | 用卡给已有账号充值续费 | —（不适用） | `username, card` |
| 500 | Verify（授权数据） | `token` | `token` |

> 卡密模式：`Key` 就是卡密；用户名由服务端按 `前4位+后6位` 派生。
> 账号模式：用户名/密码由账号决定；账号可由后台创建，或终端用卡激活(306)自助创建。

## 关键返回 `status`
| status | 含义 |
|---|---|
| 0 | 成功 |
| 500001 | 卡未使用/已被使用 |
| 500002 | 卡已冻结 |
| 500003 | 卡密/账号或密码错误、未找到 |
| 500004 | 服务异常 |
| 500005 | 用户已过期 |
| 500009 | 用户已冻结 |
| 500010 | 不允许换绑 |
| 500011 | 需要换绑（机器码不符） |
| 500012 | 注册用户名已被占用 |
| 600009 | 换绑次数/时长不足 |
| 700010 | 时间戳超时 |
| 700011 | 未知 api |

登录(300)/注册(306)成功返回含 `token`、`expired_at`、`username`。

## Token 生命周期与续签（重要）
- 登录(300)/注册(306)成功后返回 `token`，有效期 = `min(软件设置 tokenTtlHours, 订阅剩余)`，默认 24 小时。
- 之后用 `token` 调 Verify(500) 等接口。**token 短效是有意为之**（泄露最多用一天；冻结/到期更快生效）。
- **客户端必须实现自动续签**：当 Verify 返回 `500006`(token失效) 时，自动用本地保存的凭据**重新登录(300)**：
  - 卡密模式：重发那张卡 `Key`
  - 账号模式：重发 `username/password`
  - 订阅未到期 → 拿到新 token，继续；订阅已到期 → 返回 `500005`，提示续费。
- Verify(500) 每次都会复查用户的冻结/到期：被冻结返回 `500009`，已到期返回 `500005`——即使 token 还没过期。

> 例：月卡用户 token 每 24h 过期一次，客户端凭手里的卡重登一次即无感续期，直到月卡真正到期。

## 安全说明
- 卡密、账号密码在服务端只存 **Argon2 哈希**，绝不明文。
- 登录校验一次后用 `token` 通信（`token` 落库也只存 SHA-256）。
- 未使用的卡在后台 `cards` 表是明文（这是待售的库存），一旦激活成用户即只存哈希。
